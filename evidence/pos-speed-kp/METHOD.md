# POS_VEL position-loop Kp synchronization experiment

User authorization, 2026-09-21: increase Kp in 20% increments, run ten different timed waypoint tests, measure settling for every joint and target arrivals within 20% of one another. Follow the [SDK register safety instructions](https://github.com/i2rt-robotics/i2rt/blob/main/i2rt/motor_config_tool/dm_motor_registers.md).

The controlled variable is actuator `KP_APR`, not the cached MIT host Kp. Baseline fresh SDK survey: arm IDs 1–6 all `KP_APR=54`, all seven actuators disabled (`0x0`); modes 2 on the arm and 1 on the linear gripper. Each proposed gain change is bounded by 20% of the independently read current gain. Experiments write RAM only. No save-to-Flash command is used. Registers are read and written through SDK APIs by a single process/thread with exclusive CAN ownership, after the live app shuts down at verified rest. Each write has an independent read-back. A second complete survey checks unchanged modes, scaling, protection, acceleration/deceleration, speed limits, speed-loop gains, integral gain, IDs and bus rate. A failed/partial operation archives exactly what was written and leaves the actuators disabled for inspection.

`preflight.json` fixes ten free-space joint targets, an initial approach, and a safe return from each target. Joint positions differ by meaningful amounts in all six axes. The sequence alternates direction and varies amplitudes; it does not start or finish each measured trial at the supported rest. The same targets, order, 0.15 rad/s speed ceiling, operator derivative limits and SDK planner are used for each gain round. Actual plans begin at measured positions, so encoder-scale initial residuals can produce small duration differences. Planned durations and physical measurements are recorded separately. Automatic excursions stay strictly below 0.49 rad; offline checks use a 0.48 rad margin. No large-cruise exception applies.

Settling time is measured from the SDK motion-reference start, not request submission (which includes planning latency). For each joint independently, it is the first recorded feedback sample after the last out-of-band sample, followed by at least one second of recorded in-band feedback. Tolerances are the existing 0.2° on J1–J3 and 1° on J4–J6. The per-joint encoder timestamps are deduplicated and aligned to the SDK elapsed reference. The smallest publication-time-minus-reference-elapsed anchors the clock conversion; publication anchor spread is archived. This is not sub-millisecond clock synchronization. Sampling gaps above 100 ms invalidate settling qualification. Post-reference-end settlement delay is also reported.

A pose passes arrival synchronization when the slowest arrival time divided by the fastest is at most 1.20. A candidate requires all ten poses to pass. The initial search required directed overshoot strictly below 0.1° on all joints. After reviewing the measured timing/overshoot tradeoff, the user explicitly selected the latest profile and raised the J4–J6 overshoot limit to 0.5°, retaining 0.1° for J1–J3. `operator-selection.json` records that instruction, and the confirmation round uses those per-joint limits. Original trial verdicts are retained with their original criteria. Arrival times depend on the selected amplitudes, motion profiles and unequal accuracy bands; synchronization here does not prove identical actuator bandwidth or Cartesian path adherence. The historical one-second convergence aim is reported separately, not silently redefined for planned moves lasting several seconds.

Fresh/idle SDK motion-start checks, joint bounds, collision checking, reference velocity/acceleration/jerk limits, the 100 ms execution/feedback watchdog and the one-second sustained-oscillation detector remain active. Faults are never automatically acknowledged by this runner. Normal stopping returns to captured rest, checks ≤0.5° joint error for one second and disables. Camera remains available; manual camera checks remain skipped under the user's standing instruction. Bulk preflight, plots and tests run with motors disabled. No welder is connected or triggered.

These are encoder-based joint measurements. They do not measure independent torch position, backlash, loaded welding performance or force compliance. No stage is marked DONE by this experiment.
